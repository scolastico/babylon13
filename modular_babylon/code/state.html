modular_babylon/code/state.dm

/datum/babylon_playerOne player's record in this world (GLOB.babylon_save.player_sessions[ckey]). Babylon adds the player's drone (session.dm), play_time.dm their play time. A player's drone. The owner's record keeps the fields older saves wrote at the top of state.json ("builder", "player"); capture_session_state() still writes them from it.
/datum/babylon_tick_listenerRuns a module's step on every COMSIG_BABYLON_WORLD_TICK. Each module listens through its own listener: a datum can hold only one handler per signal and source, so two modules registering the session itself would silently replace each other's handler.
/proc/babylon_ready_clientThe client once /client/New() has finished, else null. GLOB.clients lists a client from early in New(), which then still waits on the player's game (window checks, the chat panel) for a while on a slow first load. Possessing the drone and deleting the new-player mob in that window left the rest of New() working on a deleted mob: a half set-up client stuck on a black screen with only the title music playing, until the player reconnected.
/proc/babylon_loop_failedLogs a failed loop step once a minute per step, so a recurring error cannot flood the log.
