/proc/babylon_area_evictMoves every player on these tiles (or inside something on them) out of the rectangle. may_pause: FALSE when the caller needs the tiles to stay as they are (it clears them next). all_mobs: every living mob, not only players (the tile is about to become solid).
/proc/babylon_area_protected_objectObjects the game protects (INDESTRUCTIBLE: vault parts, unique machines ...). The area tools never remove or copy them. Tutorial objects are flagged too, but only against damage.
/proc/babylon_area_removableObjects Clear and Paste remove (effects such as landmarks and lighting stay, and protected objects).
/proc/babylon_area_object_countHow many objects and mobs a rectangle holds (the per-operation cap).
/proc/babylon_area_too_fullWhy a rectangle holds too much for one operation, or null.
/proc/babylon_area_clear_tilesRemoves objects and non-player mobs from tiles; players are moved out of the rectangle first. Returns counts: list("objects", "tutorial", "mobs", "moved", "kept", "occupied"). occupied: tiles kept as they were because a player could not be moved off them. Each tile is handled within one tick: its players (also inside lockers, body bags, mechs) are moved out, then its contents go, so nobody can step or be put in between. turf_path: then the tile becomes this turf, in the same tick (Clear). keep_tutorial (a tutorial's Paste area action, room_reset.dm): tutorial objects, tutorial NPCs and builder tools (and whatever holds one) stay where they are.
/proc/babylon_area_kept_by_tutorialWhat a tutorial's Paste area leaves where it is: tutorial objects, builder tools and anything holding a builder tool.
/proc/babylon_area_player_onA player is on a tile or inside something on it.
/proc/babylon_area_rescueAfter a map load: players who walked into the footprint while it loaded, or could not be moved out before it, and now stand in a wall or a dense object are moved out. Where no free tile is found, a wall with a player in it becomes plating. Other mobs (a tutorial NPC a Paste area kept, an animal that walked in) are moved out of walls only: an NPC lying on a table or bed stays there; without a free tile it stays, logged (no wall is opened for it). away: the rectangle they are moved out of (the footprint; tests pass one with no free tile).
/proc/babylon_area_deleteDeletes one thing.
/proc/babylon_area_change_turfChanges one turf. Returns the turf at that spot (also when the change was cut short).
/proc/babylon_area_emptyA tile counts as empty for "Only empty tiles": not a wall, no mobs, nothing on it but things under the floor (pipes, cables, lattices) and hidden objects.
/proc/babylon_area_resmoothRe-smooths walls, windows and tables in and around a rectangle (after a map load).
/proc/babylon_area_smooth_nowSmooths at once whatever waits for icon smoothing in and around a rectangle. Before a map load: the loader pauses between batches, and the smoothing subsystem would then smooth these against loaded but not yet initialized atoms ("bad index" runtimes).
/proc/babylon_area_setup_pipesThe pipes and devices of a loaded copy, instead of tg's template setup (which builds the copy's pipenets at once and then crashes or leaves split nets where they meet existing ones, especially devices such as a pump next to a vent):
/proc/babylon_area_pipe_initSets up one pipe or device (multi-z pipes also expand). TRUE when it got to the end.
/proc/babylon_area_drop_pipenetLets go of a pipenet on the paste edge (step 3 above). TRUE when it got to the end.
/proc/babylon_area_one_way_nodesPipes in a rectangle that list a pipe which does not list them back (tests).
/proc/babylon_area_materialsTurfs and structures Fill and Border offer: list(list("path", "name", "group")), and the same as a lookup by path text.
/proc/babylon_area_materialThe material for a path text, or null when it is not offered.
BABYLON_AREA_CLIP_VERSIONThe stored clip format. Bump it when the clip's fields change: a clip stored in another version is refused with a clear message (babylon_area_clip_from_data), never pasted half understood. 1: the first format (a list of every tile, then a palette); 2: palette + grid, sizes measured.
BABYLON_AREA_SNAPSHOT_BYTESThe most one stored area (a Paste area's snapshot) may take, measured as its JSON. Checked wherever a snapshot is made, copied or loaded (babylon_area_clip_data_problem).
/proc/babylon_area_storableA setting value JSON can carry (with babylon_area_store_value): null, a number, a text, a type path, or a list of those (two levels deep). References to atoms are not.
/proc/babylon_area_store_valueA storable value as JSON data: paths and lists are wrapped so they come back as they were.
/proc/babylon_area_clip_data_problemWhy stored clip data can't be pasted (missing, another version, damaged, or over the size cap), or null. size: its JSON's length when the caller knows it (a Paste area caches it); otherwise it is measured here. Never a size the data says about itself.
/proc/babylon_area_kb"38 KB"
/proc/babylon_area_clip_from_dataA clip from stored data: list("clip" = clip, "missing" = types that no longer exist) or list("error" = why not). A type this server no longer has is left out (a turf becomes plating), so a stored room never breaks the map load.
/proc/babylon_area_entry_path_text"/obj/structure/table" from a map entry ("/obj/structure/table{\n\tdir = 4\n\t}").
/proc/babylon_area_entry_typeThe map entry's type when it exists under base, else null.
/proc/babylon_area_entry_validA stored map entry is one plain entry as babylon_area_metadata() writes it ("/path", or "/path{" plus lines that each start with a tab, then "}"): nothing can start a second entry. Its type must exist under base, and an object's must not be harmful (the spawn blocklist).
/proc/babylon_area_clean_stored_contentsStored container contents with only existing, harmless item types (depth as in a capture).
/proc/babylon_area_captureCopies a rectangle (south-west and north-east corners). Protected (indestructible) tiles are left out: a paste leaves the target there as it is, so the Creative Plane's edge can't be carried elsewhere. faithful: an undo snapshot, which keeps every other turf as it is; a copy turns turfs the materials list does not offer (lava, hull, airless floors ...) into plating.
/proc/babylon_area_copyableObjects a copy takes along: not hidden effects, projectiles or holograms, nor anything a save leaves out (babylon_skip_save(), persistence.dm: tutorial NPC gear and whatever else opts out).
BABYLON_AREA_CLIP_FIELDSFields a copy writes into its map on top of the save engine's map fields: state that a save keeps in its records, but that a pasted object must have while it initializes.
/proc/babylon_area_metadataThe map vars of an object or turf ("{\n\tdir = 4;\n\t...}"), from the save engine's own field list (babylon_save.map_fields(): build state, pipe layers, cable links, access, and the map link fields that link buttons, doors, cameras, radios ...) plus BABYLON_AREA_CLIP_FIELDS, and for floors their air. Only values that differ from the type's are written. faithful (an undo snapshot): an APC keeps its areastring; a copy builds its APC for the area it lands in.
/proc/babylon_area_capture_settingsAn object's settings that are applied once it exists, as a restore applies them: the save engine's extra_fields (babylon_save.setting_fields(): creative machine settings, pump, filter and scrubber modes ...) that differ from the type's. Null if there are none.
/proc/babylon_area_restore_settingsPuts captured settings (babylon_area_capture_settings) on a pasted object.
/proc/babylon_area_reconcilebabylon_after_restore() on a pasted object. TRUE when it got to the end.
/proc/babylon_area_stored_extra_forA stored extra limited to the setting fields the save engine keeps for this object's type (plus keys that are no variable, for babylon_after_restore), like a loadout's settings.
/proc/babylon_area_restore_extraA pasted object's settings, reagents and contents. TRUE when it got to the end.
/proc/babylon_area_is_containerClosets and storage items: their contents are copied too.
/proc/babylon_area_capture_reagentsThe reagents in a holder (an empty list for an empty holder), or null without one.
/proc/babylon_area_capture_contentsThe items in a container, recursively for storage items (a medkit in a locker).
/proc/babylon_area_restore_contentsReplaces a container's items with copied ones.
/proc/babylon_area_map_textThe clip as a map (TGM). skip_space: tiles that were space are left as they are. no_apc: tile indexes ("dx,dy") whose APCs are left out (the target area already has its own). The clip as map text (a single-level TGM map), for tests; files are written from the pieces.
/proc/babylon_area_map_piecesThe clip as a TGM map in pieces of at most BABYLON_SAVE_PIECE_BYTES, written with babylon_write_pieces() (persistence.dm) like a save's level maps.
/proc/babylon_area_id_mapOld tutorial id => new id for pasting a clip. mode: "auto" (the first free "_2", "_3" ...), "custom" (suffix) or "keep". ignore: objects about to be removed (their ids are free). Returns list("map" = ids, "suffix" = text) or list("error" = why).
/proc/babylon_area_rewrite_settingsA tutorial object's settings for its copy: links to copied objects use the new ids, zones, picked tiles and stored areas (their origin) inside the copied area move with it. Links and places outside the copy stay as they were.
/proc/babylon_area_placeBuilds a clip with its south-west corner on origin: clears the tiles it covers (players are moved aside), loads the copy as a map, restores contents and reagents, then recreates its tutorial objects. id_mode/suffix: how tutorial ids are given ("auto", "custom", "keep"); the map is worked out right before the objects are made, as other builders may have taken ids while this paused. If the chosen way no longer works it falls back to "auto"; counts gets "suffix" and "id_note". Returns an error or null; a place cut short by a runtime in its own body returns the first line's text (every success path returns null explicitly). keep_tutorial: a tutorial's Paste area (babylon_area_clear_tiles); the clip has no tutorial objects then.
/proc/babylon_area_air_flagsChangeTurf flags for a tool: a room's floor keeps its air; a new floor where there was space or a wall gets normal air (its type's), never the vacuum of the space it replaces.
/proc/babylon_area_turf_recordWhat a turf was, to put it back on undo: list(x, y, z, type, dir, air).
/proc/babylon_area_putPuts a material on tiles (Fill and Border). journal: gets the turfs' old states ("turfs") and the structures made ("made"). Returns counts: list("changed", "locked", "skipped", "occupied"). occupied: tiles left alone because a player could not be moved off them.
/proc/babylon_area_not_copied"Not copied: 2 mobs (NPC spawners come along and make their NPC again), floor markings."
/proc/babylon_area_tutorial_inTutorial objects inside a rectangle.
