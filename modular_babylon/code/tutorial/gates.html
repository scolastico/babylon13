BABYLON_TUTORIAL_GATE_DEPTHMost gates one evaluation wave goes through in a row.

/proc/babylon_tutorial_gates_liveEvery gate's state in a run, for the wand's Test run tab.
/proc/babylon_tutorial_input_modeHow a trigger counts as a gate input, for the configure window: "gate", "live" or "latched".
/proc/babylon_tutorial_gate_indexInput id => the gates that list it as an input, in placing order. Built once per tutorial version. The lists are never changed after they are built: callers may iterate them while a wave changes the tutorial.
/proc/babylon_tutorial_gates_fed_byThe gates fed by a trigger (gates that list it as an input), in placing order. Do not change the returned list.
/proc/babylon_tutorial_gate_loopA loop of gates through this one, in the order signals flow (["a", "b", "a"]), else null.
/proc/babylon_tutorial_gate_settle_orderThe pending gates (gate => TRUE) in settle order: placing order, but every pending gate a gate takes as an input comes before it (depth first). A gate already being visited (a loop) is not waited for.
/proc/babylon_tutorial_gate_operationsOperation key => label, for a number gate input.
/proc/babylon_tutorial_gate_operation_takes_valueOperations that use a value (a constant, or another number gate's number).
/proc/babylon_tutorial_clean_gate_inputsCleans a number gate's inputs: list(list("id", "op", "amount", "source")), at most BABYLON_TUTORIAL_IDLIST_MAX entries. Missing parts get defaults (count up, 1, a constant).
