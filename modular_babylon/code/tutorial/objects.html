/proc/babylon_tutorial_rewrite_linksReplaces an id in every setting that links to other objects. Returns the ids of the objects changed.
/proc/babylon_tutorial_links_fieldWhether a field links to other tutorial objects by id. Every place that follows, checks or rewrites links (references, issues, renames, pasted copies) goes through this and the two procs below, so a new kind of link field only has to be taught here.
/proc/babylon_tutorial_value_idsThe ids a setting value links to, in order, each once.
/proc/babylon_tutorial_value_renamedA setting value with its links renamed: rename is old id => new id; other ids stay.
/proc/babylon_tutorial_valid_idIds: letters, digits, _ and -, 1 to BABYLON_TUTORIAL_ID_MAX characters.
/proc/babylon_tutorial_unique_idA fresh id: prefix plus the lowest free number ("zone1", "zone2" ...).
/proc/babylon_tutorial_findThe tutorial object with this id (the first one placed, if ids are duplicated).
/proc/babylon_tutorial_resolveThe atom an id stands for: a marker's object (or tile), a spawner's NPC, a button ...
/proc/babylon_tutorial_objects_ofEvery tutorial object of a category ("trigger" ...), in placing order.
/proc/babylon_tutorial_marker_targetsMarkers and NPC spawners by id, for the Creative panel's teleport list: id => object.
/proc/babylon_tutorial_kindskind key => type path, for every placeable tutorial object.
/proc/babylon_tutorial_fieldOne settings field. type: text, longtext, number, bool, choice, typepath, id, idlist, gateinputs (a number gate's inputs, gates.dm), zone, tile (one picked tile: list(x, y, z)), effects, loadout (a stored inventory, inventory.dm), event (a round event the Creative panel offers, world_actions.dm) or area_clip (a stored area, room_reset.dm: only the server stores it, from the builder's world-edit selection; the window sees a summary). options: list(list("value", "label")). filter: categories an id may refer to. when: list(other key = list(values)) — the field applies only while that setting has one of them. search (typepath and loadout fields): "creative" searches and allows what the Creative panel's Spawn tab does (babylon_creative_search, babylon_creative_spawn_blocked); "any" allows every type under base (removing things); null: the default tutorial rules (babylon_tutorial_type_allowed).
/proc/babylon_tutorial_optionsChoice options from value = label pairs.
/proc/babylon_tutorial_schemaThe schema of a tutorial object type (cached per type).
/proc/babylon_tutorial_field_activeWhether a field applies with the object's current settings (its "when" condition).
/proc/babylon_tutorial_clean_valueCleans a value for a field: list("value" = clean value) or list("error" = why it was refused).
/proc/babylon_tutorial_type_allowedType paths a builder may pick for a typepath field.
/proc/babylon_tutorial_search_typesUp to 30 type paths under a field's base matching a search (name or path), for the window.
/proc/babylon_tutorial_overview_warningsProblems with the tutorial as a whole, for the wand's overview: list(list(text, ref)), ref naming the object to open (or null). Every object's own issues are included. Cached until the tutorial changes, for at most a second.
/proc/babylon_tutorial_trigger_successorsThe triggers that can start listening once this trigger fired: those waiting "After" it and those its Enable actions switch on.
/proc/babylon_tutorial_reachable_triggersTriggers that can ever start listening: from those listening at the beginning, following "After" links and Enable actions. Returns trigger => TRUE.
/proc/babylon_tutorial_reachability_warningsWarnings for triggers that can never start listening; "After" loops are named as such.
/proc/babylon_tutorial_overview_textsThe overview warnings as plain text (tests, logs).
/proc/babylon_tutorial_listen_fields"Starts listening" and "After": when a trigger (or gate) begins to watch.
/proc/babylon_tutorial_expand_actionsAction ids plus every follow-up action they run, recursively, each once (in order).
/proc/babylon_tutorial_object_onThe object a marker on this tile stands for: a living mob first, then machines and structures, then items. Tutorial objects and effects never count.
