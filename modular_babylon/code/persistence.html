modular_babylon/code/persistence.dm

/proc/babylon_save_textText as a save writes it: without BYOND's \proper/\improper markers. They are stored as bytes that are not UTF-8, and the file writer dropped them, so a save whose text held one came out shorter on disk than written (names of objects made during play carry them).
/proc/babylon_save_keeps_default_textTRUE if a save leaves this text field out because it holds the type's own value: the type default comes back on load, with its \proper/\improper marker. Written stripped, such a text would make name != initial(name) for every saved object of the type (atmos naming, fire alarms, cameras and article handling check that), and lose the marker's grammar. name is always left out when unchanged; other text fields when their default carries a marker.
/proc/babylon_true_planeA plane without its multi-z offset (PLANE_TO_TRUE). Saves and copies store this: a level loads at a z whose offset Initialize applies again (turfs, SET_PLANE_IMPLICIT), so an offset plane would be offset twice, and a level restored at another z needs that z's offset anyway.
BABYLON_SAVE_AREA_WAITHow long a save waits for a running area operation (tutorial/area_tools.dm) to end.
/proc/babylon_written_size_matchesTRUE if a file of file_size holds text_bytes of ASCII text appended in piece_count pieces, within what DM's 32-bit float lengths and sums can tell apart (see save_world_impl()).
/proc/babylon_join_in_piecesThe strings joined into pieces of at most BABYLON_SAVE_PIECE_BYTES (a single string is never split): large save files are written piece by piece (babylon_write_pieces()).
/proc/babylon_write_piecesWrites the pieces as the file at path (replacing it) and checks the result. Large DM strings spliced into one and written at once came out truncated or damaged, so every save file goes through here: list("bytes" = text bytes, "error" = text or null, "size_mismatch" = TRUE when the file on disk is not as long as its text). rust-g answers an error text when a write fails.
/proc/babylon_world_resumes_saveThis start resumes a saved world (the supervisor staged its state). Round-start rolls that only fit a fresh map (decay, area spawns, station traits) stand back for the whole start; atoms ask babylon_loading_saved_map(), which ends when the restore finished.
/proc/babylon_init_depth_restoreFor a catch around code that creates atoms: drops the initializing atoms a runtime left on the stack (depth: length(SSatoms.babylon_initializing) before the try).
