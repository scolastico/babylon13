Upstream integration hooks
modular_babylon/UPSTREAM_HOOKS.md

Babylon is opt-in: compile babylon.dme (the drone builder) and babylon-station.dme (normal tg rounds on the map catalog's station maps). The upstream tgstation.dme is unchanged. The fifteen modified upstream DM files use hooks guarded by BABYLON_BUILDER and marked BABYLON13. Ordinary SPLURT builds compile those blocks out.

Both Babylon builds define BABYLON_BUILDER (any Babylon cluster world). Each also defines exactly one game build define, checked at compile time in modular_babylon/__DEFINES/babylon.dm: BABYLON_DRONE (babylon.dme, the drone builder) or BABYLON_STATION (babylon-station.dme). Hooks that only fit the drone builder are guarded with the positive #ifdef BABYLON_DRONE, never with "not BABYLON_STATION", so a third build gets none of them by accident: the announcement suppression (priority_announce.dm), the round-start divergency report, and the 255x255 single-level sizing in mapping.dm. All other hooks (admission, showcase visitors, persistence preloading, material pruning, the Discord button, the SQL message guard, the master's restore wait) apply to both builds. The station build keeps the full CentCom map (its shuttle docks are needed for a round) and skips the Interlink (ABSOLUTE_MINIMUM).

Module split: world_flags.dm (GLOB.babylon_world, the supervisor's world parameters and babylon_world_ready()), state.dm, persistence.dm (engine, with per-build hooks checkpoint_hold, checkpoint_mobs, capture_session_state, restore_session_state), admission, control, AFK, showcase, spectator, SFW, links, storyteller, moderation, world players, interface, music and play time are in both builds. rules.dm (Babylon's world rules: one 255x255 level, no events, storyteller subsystem, weather or minor mapping), session.dm, drone recovery, builder experience, lore, vault, survival, silicons and research are only in babylon.dme; station_session.dm only in babylon-station.dme.

The wrapper also defines upstream's ABSOLUTE_MINIMUM flag to skip the separate Interlink/cafe map loader. Builder behavior, restricted observer interfaces and lore papers live under modular_babylon; lore placements are applied to the fresh upstream map at preparation time, without a copied map.

Babylon is safe for work. modular_babylon/code/sfw.dm disables inherited ERP content through proc and var overrides only (no upstream edits): it locks DISABLE_ERP_PREFERENCES/DISABLE_LEWD_ITEMS on, filters lewd interactions, emotes, research designs and chemistry, removes the Plug13 verb, and opens the new Babylon-only tgui/packages/tgui/interfaces/BabylonInteraction.tsx instead of SPLURT's MobInteraction window. After an upstream merge, re-check newly added lewd interactions, designs, reactions and verbs against it.

The Creative panel (modular_babylon/code/creative/, both builds) adds the new Babylon-only tgui/packages/tgui/interfaces/BabylonCreative.tsx (with its BabylonCreative.test.tsx); no upstream file is edited. After an upstream merge, re-check new round events and spawnable types against its blacklists (babylon_creative_event_blocked, babylon_creative_spawn_blocked).

Babylon has no storyteller yet. modular_babylon/code/storyteller.dm runs an inert /datum/storyteller/babylon in every Babylon world (no events, no antagonists), refuses the storyteller vote and any other storyteller, and keeps tgstation's random events off, again through overrides only. Station worlds run SPLURT's storytellers without a vote: DEFAULT_STORYTELLER from the config, else /datum/storyteller/default (SSgamemode's choice without a vote); Creative Plane maps and tutorial worlds are inert like Babylon. After an upstream merge, re-check SSgamemode's set_storyteller/init_storyteller, the storyteller vote and SSevents.spawnEvent against it; the native smoke test asserts it.

Round control in station worlds (modular_babylon/code/station_round.dm, station build only) needs no upstream edits either; it overrides procs: SSticker setup, standard_reboot and fire (the reboot HUD text), /world/Reboot, SSgamemode handle_pre_setup_roundstart_events/handle_post_setup_roundstart_events, SSdynamic.on_latejoin, and on the title screen (Skyrat's modular_skyrat/modules/title_screen) /mob/dead/new_player get_title_html (it inserts Babylon's colours/font, the round status and the owner's Start round button after the menu's <div class="container_nav">), Topic and Login, plus /mob/dead/get_status_tab_items and the tg lobby HUD's time_remaining_str. The round is held with SSticker.SetTimeLeft(-1) and started with start_immediately. After an upstream merge, re-check the title screen markup (container_nav), declare_completion → standard_reboot, the ticker's pre-game countdown and setup(), and the storyteller's roundstart event procs.

Station saves (modular_babylon/code/persistence_levels.dm, station build only) need no upstream edits either. A world restoring from a save (its data/next_map.json names _maps/babylon/saved) overrides SSmapping Initialize (the map config's level traits come from the save, no height autosetup, no space/wilderness levels), LoadGroup (only the "Station" group loads), setup_ruins, setup_rivers, run_map_terrain_generation, run_map_terrain_population and SSminor_mapping.Initialize; every override falls through to tg's proc otherwise. Shuttles are saved as the turf beneath them (baseturf_skipover/shuttle in the tile's baseturfs) and stationary docks keep shuttle_id, size, roundstart_template and json_key in the saved map. After an upstream merge, re-check SSmapping.Initialize/loadWorld (new generated levels or terrain steps must be skipped when restoring), the stationary port vars and /obj/docking_port/mobile/jumpToNullSpace (how a shuttle tile's underlying turf and area are found), and /datum/map_config/LoadConfig's trait defaults. The master's restore-wait hook (code/controllers/master.dm, both builds) counts its waiting rounds as loop iterations: a station restore takes long enough that the failsafe otherwise restarted the controller in the middle of initialization.

The Creative Plane maps (modular_babylon/code/creative/plane.dm, station build only; maps generated by tools/babylon/gen_creative_plane.py) have no shuttle docks. On any map without the emergency_home dock the module overrides SSshuttle.canEvac (refused with a message), SSshuttle.CheckAutoEvac (no crew-death autocall) and /obj/docking_port/mobile/emergency/request (any other call is refused and logged); without cargo_home, the cargo console's ui_act refuses "send"/"loan" with a message; and /obj/docking_port/mobile/request ignores a request to a missing (null) dock. Maps with the docks are unchanged. The creative canister (creative/machines.dm) overrides portable_atmospherics connect/disconnect to reconnect itself to the port on its tile (mapped plane, restored saves). After an upstream merge, re-check those shuttle procs, the cargo console's actions and portable_atmospherics/connect; the station smoke asserts them on every Creative Plane map.

modular_babylon/code/moderation.dm grants lobby admins (BABYLON_ADMINS) full game-admin rights on admission, removes mentors (no mentor is loaded, admins are not made mentors, Mentorhelp and Mentorwho are gone) and relays adminhelps to the supervisor for the Discord ahelp feature; Discord replies use the game's external admin PM (TgsPm). All through overrides. After an upstream merge, re-check MessageNoRecipient, reply_to_admins_notification, receive_ahelp, TgsPm and the Skyrat mentor module against it.

modular_babylon/connection.dm is shared with the standalone lobby and owns the structured BABYLON_SESSION records and final client deletion hook. Admission, world joins, lobby transfers, shutdown and AFK returns supply their context and known reason; moderation.dm also wraps /world/IsBanned to record pre-client refusals. Small BABYLON_BUILDER hooks retain reasons before upstream disconnects in client_procs.dm, both admin player panels, admin/SQL bans, server maintenance, IP intelligence, TGUI telemetry, kick mines and the maturity subsystem. After an upstream merge, scan client deletions and delayed deletions for new known causes; ordinary builds compile without these hooks.

modular_babylon/code/research.dm replaces the research point bank and queue: a techweb researches one selected node at a time, all income (through add_point_list) goes towards it capped at its price, research_points holds that progress, income without a target is dropped and switching targets starts over. The target is saved with the world. After an upstream merge, re-check add_point_list, research_node, complete_experiment, the queue procs and the R&D console / PDA research_node and ui_data against it. sfw.dm (both builds) removes designs no world offers (ERP; in Babylon also pAI, AI core, MMI, positronic brain) from every node in SSresearch.calculate_techweb_nodes and refuses them in /datum/techweb/add_design; /datum/techweb_node/Initialize is not usable for that, because upstream's initialize_all_techweb_nodes calls it on the old, empty node list.

modular_babylon/code/silicons.dm removes pAIs, station AIs, MMIs and positronic brains, which no one can play: pAI cards, AI cores and loose MMIs/posibrains delete themselves on creation (wreck, saves, loot), their designs are removed, the plasteel "AI core" recipe and the PDA vendor's pAI cards are gone, and ghosts get no "Enter Soulcatcher" button. After an upstream merge, re-check new sources of pAI cards, AI cores and ghost-joinable silicons against it.

modular_babylon/code/interface.dm trims the game window through overrides and runtime winsets (the shared interface/skin.dmf is unchanged): the top bar keeps Menu, Settings, Fullscreen and Reconnect in four evenly sized columns, measured again on resize; world verbs appear in World Controls, directly after Status (including for non-admins). The station is named after the world (babylon-name, markup characters removed); the status tab drops the round ID; and verbs for systems Babylon lacks (antag tickets, OPFOR, round-end reports, votes, respawn, relays, forum/Discord-DB linking ...) are removed. After an upstream merge, check new player verbs and the infobuttons controls.

Keep these patches small. Do not copy complete upstream files from the local prototype. When upstream changes a hook's surrounding procedure, review its execution order, not just whether Git merges the text cleanly. In particular, moving restoration after simulation startup reintroduces reactor/network bugs.

BYOND 516.1686 slot quirk

DreamMaker 516.1686 (.tgs.yml) sometimes mishandles whichever variable lands on one particular internal slot. It has shown up as a proc's static list that is "invalid" (code/modules/antagonists/cult/cult_structure_altar.dm:41: error: altar_items: invalid variable, archive_items in cult_structure_archives.dm) and as a local that is plainly used but reported as warning (unused_var) (suspect_gloves in forensics_helpers.dm, loser_controller in cat_bt.dm, plant_smudge in plant_genes.dm). The reported file is never the cause: any change that adds or removes a variable anywhere in the build moves the slot onto another variable, so the same change can break one build and not the other three. Treat a build that shows it as possibly miscompiled, not as noise: the slot is used for code generation too, and a clean build only means that whichever variable holds the slot now gives no diagnostic. A local that really is never read is an ordinary warning, not the quirk. Investigate a failing runtime test and prove its cause independently of this compiler workaround. The earlier "All doors" NPC test failure was traced to live-map AI turrets adding stamina damage to the walker, together with timing-dependent completion checks. Tutorial and area-tool tests now use isolated fixtures and exact completion conditions. Moving a padding global until a runtime test passes does not establish a fix.

Recipe: add or remove one padding global (var/global/babylon_byond_1686_slot_pad_<n>) in the block for the affected build at the end of modular_babylon/code/world_flags.dm, then compile all four builds again (repeat until all are clean). The pads do nothing else; remove the block once a BYOND build fixes the quirk (check newer 516 builds when bumping .tgs.yml). tools/babylon/build_dme.py, which the Dockerfile uses for every DreamMaker run, prints this recipe when a build log shows the quirk's signature, and then fails the build (exit 1), so an image is never built from a possibly miscompiled build. A maintainer who checked that the warning is a real unused local (not the quirk) and fixed it does not need the escape hatch; BABYLON_ALLOW_SLOT_QUIRK=1 lets such a build pass anyway.

Updating upstream

git remote add upstream https://github.com/SPLURT-Station/S.P.L.U.R.T-tg.git
git fetch upstream
git merge upstream/master

Skip remote add if the remote already exists. Preserve upstream history; do not squash upstream into this repository or force-push over its branches.

After every merge:

  1. Review every BABYLON13 marker and the standalone wrapper.
  2. Rename newly introduced .github/workflows/*.yml / *.yaml files with a .disabled suffix before pushing. Keep repository Actions disabled too.
  3. Compile ordinary tgstation.dme, production babylon.dme, and the local babylon-test.dme test build.
  4. Exercise a fresh wreck, a save/reload, pipe expansion, vent/alarm links, materials, airlock groups, and drone death/respawn. Use an isolated process and disposable world; never point tests at a player's running instance.
  5. Run services/supervisor/smoke_native.py and smoke_station.py (with its stability step): a new upstream stack_trace in a restore path stops worlds from starting, and a new random roll in an Initialize changes saved worlds on every restart.

The private prototype's six upstream hooks were carried forward. Its chat transcript patch, personal config, owner name, repair object IDs, saved world, and training/admin subsystem were deliberately not imported.
