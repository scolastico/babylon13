saved_level_sourceSaved level z (as text) -> the generation directory holding its z.dmm.

tick_listenersOne /datum/babylon_tick_listener per module that steps with the world tick.
turf_metadata_cache"type|air" -> the saved map entry of a turf that keeps its type's values (one save only).
typed_fieldsSaved fields of one type and its subtypes only (a name such as "status" means different things on other types). Their values are state that the type's mapload Initialize would otherwise decide anew; babylon_after_restore() reconciles them after a restore or a paste.

begin_level_captureAt the start of a capture, while the world is paused: the build takes the set of changed levels for this save and starts a new one.
capture_machine_frameA machine frame's construction progress: the parts put in (objects, which are also saved as its contents, and stock parts, which are kept only as their type) and what it still needs.
capture_playersWrites state["players"]: every player's snapshot, by ckey. Nothing for a tutorial snapshot (babylon_world_saves_characters()).
checkpoint_skipped_tilesTiles saved as what lies beneath them, without their contents: list(turf = list(turf type, area type)). The station build leaves its shuttles out this way (they load again at their docks). Babylon has none.
checkpoint_tile_extrasExtra map entries per tile, as list(turf = list(entry, ...)): things that only existed while the map loaded and must load with it again. Babylon has none; the station build writes the transport id landmarks its lifts and trams consumed.
ensure_admin_spectatorTurns the client's new-player mob into a spectator ghost once, after it finished connecting. Later the admin may possess or aghost as they like; the world never takes them over.
estimated_pause_secondsSeconds a save pauses this world: the last capture's time, else a guess for the build. The levels' last capture times add up for the levels the next save captures (a level that was never captured in this run counts as a whole first save divided by the levels).
hide_save_verbsWorlds that are not saved (babylon_world_saves()) show no save verbs.
level_fileThe map file a saved level is written to inside its generation directory.
level_save_failedA save failed: levels it took as changed stay changed for the next one.
level_savedAfter a successful save: the build's bookkeeping of changed levels.
load_resume_dataReads data/babylon/resume-state.json (staged by the supervisor) once: resume_data, and resume_records by save id. Returns the state, or null for a fresh world.
log_non_ascii_textDiagnostics for a state.json whose size is off: where its text holds characters outside ASCII (json_encode should leave none), with some context, for the first few hits.
map_fieldsThe fields of this atom's type that go into a saved map (structural_fields, map_link_fields and type_metadata_fields), cached per type. The area tools' copies use the same list.
object_type_fields_ofThe object_type_fields (state.dm) that apply to this atom's type.
owner_playerThe world owner's record, once they have one (Babylon: from SSbabylon_builder's start on).
persisted_levelsThe z-levels a checkpoint saves, in load order. Babylon: its one station level.
read_afk_timeoutReads babylon-afk-timeout into afk_timeout. FALSE (with boot_error set) when it is invalid.
record_creative_canister_portsRecords every restored creative canister's port state as restore_world() leaves it.
remove_regenerated_copiesOnce the world finished initializing after a restore (both builds' boot, before ready): what the load made anew on top of the save that the companion rule cannot see (made outside an Initialize: a LateInitialize, a subsystem, a timer): an unsaved object of the same type on the same tile as a saved one is a regenerated copy, and the saved one, with its state, stays. Restricted to objects without a save id that are no companions, on saved levels.
remove_saved_companion_copiesAfter a restore: a saved object of the same type on the same tile as a companion made during this load is a copy an older save kept; the companion stays (its maker holds it). The same holds for CentCom, whose template loads again on every start (Babylon saves its tiles with the level).
restore_containersCreates the saved objects that hold other saved objects but are not in the saved map (the station's player characters), before restore_world()'s records pass: they get their save ids in restored_atoms, so records whose parent they are find it. Returns the records to restore with the others (their own records and those of their contents). Babylon has none.
restore_lost_supermatterSaves before version 7 dropped the supermatter shard from the engine's secure crate, which makes progression impossible. Such a world without any crystal gets the shard back there. Only older saves are repaired: a crystal lost in play afterwards stays lost.
restore_machine_frameRebuilds the frame's part lists from its board and the saved progress. Without them a frame with a board installed could neither be finished nor emptied.
restore_playersRestores state["players"] (or a build's legacy equivalent): a record for every saved ckey.
restored_level_zThe z a saved turf record's z is loaded at in this world. Babylon: the same.
reusable_levelThe generation whose files and records a level can reuse because nothing changed it since, or null to capture it. Babylon always captures its one level.
save_format_versionstate.json "version" this build's checkpoints are written in, for migrations only (the layout is writes_level_files()). Babylon: BABYLON_STATE_VERSION. The station build overrides it (BABYLON_STATION_STATE_VERSION).
save_levelSaves one z-level: list("map_pieces" = its .dmm (a single-level TGM map) in pieces, "records" = saved objects (state.json "records"), "turfs" = room air and temperature (state.json "turfs")). Records and turfs carry their z when writes_level_files(); Babylon's do not.
save_refusalA build's own reason not to save now, or null. The station build refuses after its round ended (persistence_levels.dm).
save_worldSaves a checkpoint. Worlds that are not saved (babylon_world_saves()) refuse unless forced. for_tutorial: a tutorial snapshot (a submission or save back, tutorial/submit.dm), forced, that never becomes the world's checkpoint (no latest.json, no level reuse) and keeps no characters or per-player records (babylon_world_saves_characters()). The caller deletes it once it was copied.
saved_gas_mixThe air a saved open turf loads with. Planetary turfs keep their planet's mix (their own initial_gas_mix, e.g. the ice moon's): writing their current air there would make every visited tile a new planet with that air for good. Other turfs load with their current air.
saves_effectEffects are not saved (spawners, helpers, overlays), apart from decals. The station build also keeps landmarks that its rounds need.
saves_recordWhether an object on a tile gets a state.json record (and a save id), or only its entry in the saved map. Babylon records everything; the station build leaves out scenery (plants, rocks, decals), which was most of a planet level's objects.
saves_turf_airWhether a non-space turf's temperature and air go into state.json "turfs" (the map's initial_gas_mix already holds its air). Babylon keeps every one.
schedule_autosaveStarts the autosave countdown every autosave_interval (Babylon 15 minutes, station worlds the supervisor's babylon-autosave-minutes, default 30) while players are connected (both builds' tick_players()). Worlds that are not saved never count down.
setting_fieldsThe extra_fields of this atom's type (settings applied after the object exists: creative machine settings, pump and filter modes ...), cached per type. The area tools' copies use them.
tick_worldOne step of the world's loop, once a second while the world runs: the build's player loop, then COMSIG_BABYLON_WORLD_TICK for the modules' own steps (play time, round control ...). Defined only here; modules register for the signal (tools/babylon/test_tick_override.py).
turf_decal_entriesThe tile's floor decals (warning lines, trim) as map entries. A turf decal turns into an element on its turf when it loads and deletes itself, so without these every save lost them.
type_fieldsThe typed_fields that apply to this atom's type.
type_metadata_fieldsExtra map variables written for this atom's type in the saved map (structural_fields are written for every type). Babylon has none; the station build adds the docking ports' setup.
writes_level_filesThe checkpoint layout, separate from save_format_version() (which only drives migrations): FALSE (Babylon) writes one map.dmm and records and turfs without z; TRUE (the station build) writes a z.dmm per saved level and a z on every record and turf. Driver.prepare reads the layout by the world's build (services/supervisor/fixtures/README.md).
