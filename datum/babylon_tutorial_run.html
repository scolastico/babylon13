babylon_tutorial_run
/datum/babylon_tutorial_run

Vars

action_logEvery note, in order, for the Test run tab (the last 20).
action_notesAction => what went wrong the last time it ran in this run (an NPC that gave up walking, a door that would not open ...): its issues show it as "Test run: ..." (wand checks).
bodiesPlayer key (ckey, or a ref for a mob without one) => weakref to their body: the living mob they play, or the one they left when they died or ghosted (players.dm).
current_triggerThe trigger whose actions are being performed (actions use it for "until the next step").
enabledtrigger => world.time it started listening (only listening triggers are keys).
firedtrigger => times it fired.
gate_logEvery stop, in order, for the Test run log.
gate_pendingGates that started listening since the last check (gates.dm settle_pending_gates()).
gate_statesGate => its state: a logic gate's output, a number gate's condition (gates.dm).
gate_stopsGate => why the run stopped a loop or an over-long chain at it (the wand shows it).
gate_valuesNumber gate => its number in this run (missing: still its start value).
gate_waveThe gates being updated right now, outermost first: the current evaluation wave's path.
gate_wave_updatesGate updates made in the current wave, and whether the wave ran out of them.
history"trigger>action" for every action performed, in order (tests and the log).
hitstrigger => TRUE: a player's event (a press, a use, a phrase) waits for the next check.
imagesImages every player sees: image => list(until, anchor weakref, clear_on triggers).
last_firedtrigger => world.time it last fired.
last_statetrigger => whether its condition held at the last check (edge-triggered kinds).
level_statesLevel trigger (zone, holding, condition) feeding a listening gate => its sampled state.
moversNPC => its walk (/datum/babylon_tutorial_npc_move, npc.dm) started by a Move NPC action.
objectiveThe objective on every player's screen, if any ("[player]" is filled in per player).
objective_shownWeakrefs to the mobs the objective alert was put on (to take it off again).
pointingSpeakers pointing again and again: list(speaker weakref, target weakref, until, next, clear_on).
previewA throwaway run previewing one action for one builder: never touches the objective alert.
preview_mobThe builder a preview runs for: the run's only player.
reset_npcsThe run was started with "Reset NPCs" (Run again does the same).
snapshotsPlayer key => what their body looked like and wore just before it died (players.dm).
spawned_countObjects the run's Spawn object actions created so far (BABYLON_TUTORIAL_SPAWN_RUN_CAP).
timersTimers of actions still waiting.

Procs

add_playerAdds a player (or moves their key to this new living body). key: the player's key when the body does not carry it yet (a rebuilt body before the player is put in).
audienceThe mob each player is now (their body, or their ghost): who reads messages and sees images.
body_deletedA tracked body is being deleted. A dead one (captured at its death) keeps its player in the run and the snapshot remembers where it was last; a living one means the player left the world.
body_ofThe body a player key plays or left behind; null when it is gone.
check_triggersOne check of every listening trigger.
claim_spawnsCounts count new objects of action against the run's cap (BABYLON_TUTORIAL_SPAWN_RUN_CAP): every action that makes objects (Spawn object, Give item, a Set inventory loadout) shares it, so a repeating trigger can't fill the world. FALSE, with a note for the builder, when they would go over it: the action then makes nothing.
clear_triggers_forThe triggers whose firing ends something an action shows now ("until the next step"): the triggers that start listening after the trigger being performed, or the chosen one.
clear_waiting_forA trigger fired: arrows, highlights and repeating points waiting for it end.
completeThe tutorial is done: every player sees the completion screen and no trigger fires any more.
continue_pointingSpeakers point again every 4 seconds while their point action lasts.
enabled_sinceworld.time the trigger started listening.
expire_imagesExpired images go; players who joined or reconnected since see the ones still running.
fireFires a trigger: what waited for it stops, the next step's triggers start listening, its actions run in order, each after its own delay, and the gates it feeds see it fire.
forgetA tutorial object was deleted: drop every reference to it.
gate_numberA number gate's number in this run.
gate_startedA gate started listening: it is false until the next check evaluates it.
gate_stoppedA gate was switched off: it turns false without its own actions; the gates it feeds see it.
hitA player's event for a listening trigger (a press, a use, a phrase).
image_viewersThe clients that see the run's images: every player's (also as a ghost).
image_with_keyThe image the run shows for a key, if any.
input_stateWhether a trigger counts as true for a logic gate: a gate by its state, a level trigger by its live condition, an event trigger once it fired in this run.
is_playerWhether a mob (an item's user, a button's presser) counts as a player of this run: a known player, or a living mob a player controls (a client or a player's key). Never a client-less mob nobody plays.
mark_firedCounts a firing: a once-trigger stops listening, what waited for it ends and the triggers "After" it start listening.
note_actionSomething an action could not do in this run (a builder-visible note): the action's issues say "Test run: ..." until the run ends, the Test run tab lists it and the game log has it. A preview tells its builder instead.
notify_gatesA trigger fired (fired = TRUE) or a gate or level input became false (fired = FALSE): every listening gate it feeds updates, as one step of the evaluation wave.
on_qdeletingSomething the run listens to is being deleted: a player's body (players.dm) or the anchor of an image. One handler for both, so neither replaces the other's registration.
performPerforms an action for this run. trigger: the trigger that fired it (null for a preview). No try: a deep stack_trace (an outfit, a revive) must end only the proc it happens in.
playersEvery living player: actions that target "the player" hit all of them.
rebuild_bodyA new body from a player's snapshot, at the old body's last tile (else the start marker).
refresh_copiesOutlined copies of an atom's look (Highlight) take its look again when it changed, so a highlighted NPC that turned, lay down or picked something up never shows a stale second body.
refresh_playersPicks up every living player in the world (previews keep their one builder).
repeat_pointA speaker points at a target again and again. One entry per speaker and target: a point action performed again replaces its earlier entry (the speaker never points twice at once).
revive_playerRevives one player: their body if it still exists, else a new body made from the snapshot; then the player is put back into it. Only a player who is around to come back counts: one in their dead body or watching as a ghost. Nobody is pulled out of the lobby, an SSD corpse stays as it is and a player who plays another living body is left alone. Returns the body, or null when there was nothing to do.
run_actionsRuns a list of action ids for a trigger in order, each after its own delay (the trigger's delay first). wait: start from this delay instead of the trigger's (follow-up actions of an action, e.g. a Move NPC action's "On arrival", which already waited for their action).
sample_levelsSamples every level trigger that feeds a listening gate; a change is passed to its gates (becoming true counts as a firing for number gates). Level triggers no listening gate uses are forgotten, so they are measured afresh when one starts listening.
set_gate_stateA gate's new state (and for a number gate whether its number changed): On true / On false, then On change, then the gates it feeds update.
set_objectiveShows (or with null removes) the objective that stays on every player's screen.
settle_pending_gatesGates that started listening since the last check are evaluated once, each as its own wave: one that holds becomes true (On true, it fires, the gates it feeds see it), one that does not runs On false. On change does not run for this first evaluation. They settle in dependency order (a pending gate's pending input gates first), so a gate never reads an input gate that is about to settle; gates in a loop fall back to placing order.
show_imageShows an image to every player, for a while. anchor: the atom it is attached to; when that is deleted, the image goes. clear_on: triggers whose firing removes it early. key: what the image shows ("arrow" plus its target ...): one image per key, a new one replaces the one before, so a target never shows two arrows or two outlines (spec 12 #14). A preview does not add a second one next to the world's run's image with the same key. copy_color: the image is an outlined copy of the anchor's look (a Highlight); it follows the anchor's look as it changes.
snapshotCaptures a body's looks and equipment for a later revive in a new body.
start_gate_waveA new wave starts: its update budget is full again.
stop_gate_waveA wave stopped at a gate: the run notes it for the wand and the log.
sync_objectiveEvery living player wears the objective alert while there is one (players who joined later too).
