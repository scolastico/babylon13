Babylon 13 Lobby - Modules - Types — Proc Details

/(global)

Procs

babylon_connection_addressRoute default loopback links through the server the player actually reached. winget's "url" is the SERVER's IP:port; client.address is the PLAYER's IP and must never be used. A configured non-loopback destination stays authoritative. Keep the destination's port and query verbatim: in particular, never rebuild, log or expose an admission ticket.
babylon_session_log_lineOne record format for the standalone lobby and both world builds. JSON escapes player text, so names and refusal reasons cannot create forged log lines. Never pass tickets or URLs here.
lobby_awaitWaits at most timeout deciseconds for a request: its response, or null (also when it is still running; it then finishes in the background and its answer is dropped).
lobby_decode_payloadThe page's JSON payload as an object (assoc list); null when it is anything else.
lobby_export_startworld.Export(url) in the background: the request, to wait for with lobby_await().
lobby_flagA 0/1 flag from the page; null for anything else.
lobby_generation"save-YYYYMMDD-HHMMSS-N", the checkpoint generation format; null for anything else.
lobby_numberA number for the page; anything else from the supervisor becomes 0.
lobby_payloadA link parameter carrying a JSON payload, as lobby.js sends them.
lobby_plural"1 running world", "3 running worlds".
lobby_request_idA request id from the page: a small positive number, or 0 for a plain link.
lobby_restart_panelShown instead of the world list while the server restarts (or its supervisor is unreachable). loading.js shows the same screen when the lobby connection itself is gone.
lobby_retry_noticeA notice that sends the player back to a world, worded for the button that does it: Join on a world card, Rejoin (or Play) on a tutorial card, Edit on a pending tutorial. reason: "admission" (the world took too long to let them in), "offered" or "timeout". retry: "join", "play" or "edit" (anything else gets a neutral wording).
